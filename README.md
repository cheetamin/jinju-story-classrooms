# 우리 고장 진주 이야기

동물 유등을 클릭해 친구들의 지역 소개 자료를 감상하는 교육용 웹앱입니다. 하나의 소스로 여러 학교·학급을 운영합니다. 화면·배경·동물·유등의 순환 움직임은 유지하며, 학급 데이터는 서버에서 분리합니다.

- [현재 운영 사이트](https://jinju-animal-lantern-class44.workspace-889499.chatgpt.site/)
- [교사용 안내·새 학급 만들기](https://jinju-animal-lantern-class44.workspace-889499.chatgpt.site/teacher?new=1)
- [GitHub 소스 저장소](https://github.com/rkdrkals0227/jinju-story-classrooms)에서 버전을 관리합니다. GitHub는 소스 관리 공간입니다. GitHub Pages만으로는 이 앱의 인증·DB·파일 저장 API를 실행할 수 없습니다.

## 선생님 사용 순서

1. 사용 안내를 읽고 학교·학년·반과 번호·이름 표를 입력합니다. 학급은 1~60명, 번호는 중복 없는 1~99입니다.
2. 생성된 전시관·학생 제작실·교사 관리실의 **학급 전용 주소**를 보관합니다. 학생에게는 학급 주소·입장 코드·본인 비밀번호만 전달합니다.
3. 새 계정의 개인 비밀번호는 무작위로 발급합니다. 기존 계정의 비밀번호는 자동으로 변경하지 않습니다. 재발급할 때만 새 비밀번호가 적용됩니다.
4. 학생이 네 챕터에 글과 사진을 넣고 임시 저장·미리보기·제출을 진행합니다. PPT/PPTX/PDF도 첨부합니다.
5. 교사가 제출본을 확인·승인하면 전시관에 표시됩니다. 재수정은 다시 승인해야 하며 이전 승인본과 초안을 분리합니다.
6. 명단 마지막의 ‘교사용’은 읽기 전용 공통 예시이며 신규 학생 수·비밀번호 발급 대상에서 제외합니다. 원래 보관 학급의 체험 계정은 그대로 유지합니다.

`학급·명단·용량`에서 학교·학급 정보, 관람 범위, 학생 이름·추가·제외·복구·빈 번호로 이동, 저장 공간, 백업을 관리합니다. 번호 이동 시 작품·파일·비밀번호를 유지하고 이전 학생 세션을 종료합니다.

## 개인정보와 공개 범위

- 기본값은 **학급 코드 + 학생 개인 인증**입니다. 코드만 아는 사람에게 실명이나 학생 작품을 제공하지 않습니다.
- 교사가 명시적으로 코드 관람을 허용하면 승인본만 감상할 수 있고 이름 대신 번호를 표시합니다. 작품 본문·사진 속 개인정보까지 자동으로 익명화하지 않으므로 공개 동의를 먼저 확인해야 합니다.
- 다른 학급의 비공개 자료·계정·파일은 사용할 수 없습니다. 전체 관리자만 전체 학교 관리 권한을 가집니다.
- 검색 제외 헤더와 robots 설정을 적용합니다. 검색 제외는 인증을 대체하지 않습니다.
- 파일 캐시는 `private, no-cache, must-revalidate`입니다. 매 접근마다 인증·승인 상태를 확인하고 ETag가 같으면 원본을 다시 읽지 않습니다. 비공개 전환 시 재검증을 거쳐 차단합니다.
- 원본 파일, 백업, DB, 비밀번호, 세션, 환경 비밀값을 GitHub에 올리지 않습니다. 테스트는 가상 명단·시험용 암호를 사용합니다.

## 저장량과 무료 운영 제한

| 항목 | 기존 Sites/R2 기본값 | 제한형 Workers Free + D1 시험 구성 |
| --- | --- | --- |
| 새 파일 한 개 | 5MB | 1MB |
| 학급 파일 용량 | 64MB | 최대 16MB |
| 프로그램 파일 용량 | 512MB | 최대 100MB |
| 학급 파일 개수 | 320개 | 320개 (용량 한도 우선) |
| 학생 저장 파일 개수 | 16개, 작품 첨부는 8개 | 동일 |
| 최대 개설 학급 | 기본 100개 | 최대 10개 |
| 하루 원본 파일 읽기 | 기본 20,000회 | 동일 |

이는 **앱 내부 안전 한도**이며 공급자의 무료량·요금 상한과 다릅니다. 다른 앱의 계정 합산 사용량도 확인해야 합니다. 관리자 화면에서 전역·학급 업로드 중지, 신규 개설 중지, 용량·개수·파일 읽기 한도를 조정합니다. D1 시험 구성의 강제 상한은 올릴 수 없습니다.

이미지는 학생 기기에서 긴 변 1,600px 이하의 WebP로 압축합니다. PNG 투명도를 유지하고 외부 변환 서비스를 사용하지 않습니다. 새 한도는 기존 파일을 삭제하거나 축소하지 않습니다. 업로드가 중지되어도 글 저장과 기존 작품 데이터는 유지합니다. 원본 파일 읽기 안전 한도에 도달하면 다음 날(UTC 기준) 다시 열 수 있습니다.

전시 목록은 화면이 보일 때 90초 간격으로 갱신합니다. 사용자 요청·인증 시도와 원본 읽기 집계는 공급자의 전체 서버 사용량/청구량과 다릅니다.

## 백업·복구·학기 종료

- **전체 백업**: 교사 `학급·명단·용량 → 저장 공간`에서 명단·작품·파일 원본을 포함한 JSON을 내려받습니다. 전체 관리자도 학급별 전체 백업을 받을 수 있습니다. 계정 비밀번호/세션은 넣지 않습니다. 큰 백업은 컴퓨터에서 받고 실제 파일이 저장됐는지 확인하세요.
- **본문 백업**: 기존 버튼은 파일 연결 정보까지 포함한 텍스트 JSON입니다. 이미지/PDF 바이트가 없으므로 단독으로 파일 복구에 사용할 수 없습니다.
- **초안 복구**: 전체 백업 JSON을 가져오면 같은 번호 학생의 초안과 파일을 복구합니다. 승인본·제출본·비밀번호는 덮어쓰지 않습니다. 학생이 제외돼 있으면 먼저 학생 복구를 진행합니다.
- **다른 학급으로 복구**: 새 학급과 번호 명단을 먼저 만들고 새 관리실에서 전체 백업을 가져옵니다. 개인 비밀번호는 새 학급의 것을 사용하며 검토 후 다시 제출·승인합니다. 가져오기 중 실패하면 일부 업로드가 남을 수 있으니 미사용 파일 목록을 확인한 뒤 다시 진행하세요.
- **학생 제외**: 로그인만 중단하고 작품·파일·기존 암호 해시를 보관합니다. 원래 번호로 복구할 수 있습니다. 보관 번호에 새 학생을 넣을 수 없습니다.
- **보관 검토일/학기 종료**: 검토일을 기록하고 학급 보관으로 학생·관람객 접속을 중단합니다. 교사는 백업과 재개를 할 수 있습니다. 자동 파기는 하지 않습니다.
- **미사용 파일 정리**: 초안·제출본·승인본·제외 학생 작품에 쓰이지 않는 파일만 정리합니다. 물리 삭제 전 전체 백업을 받으세요.
- **영구 삭제**: 교사는 본인 학급, 전체 관리자는 학교 또는 개별 학급을 삭제할 수 있습니다. 대상명·비밀번호·백업 보관 확인 후 원본까지 삭제합니다. 서버 휴지통 복구는 없으며, 복구에는 로컬 전체 백업이 필요합니다. 원본 보관 학급은 삭제 보호합니다. 파일 정리 실패 시 접속 차단을 유지하고 전체 관리자에게 재시도를 요청합니다.

학교 기준에 따라 수집 목적·공개 동의·보관 기간·파기 담당자·클라우드 및 국외 저장 요구사항을 먼저 확인하세요. 이 프로그램이 학교의 개인정보 검토를 대신하지 않습니다.

## 개발 실행과 검사

Node.js 24 이상, pnpm 11을 사용합니다.

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm typecheck
```

Sites 개발에서는 기존 `.openai/hosting.json`과 `vite.config.ts`를 유지합니다. 로컬 환경 비밀값은 `.dev.vars` 또는 서비스 비밀 설정에만 저장합니다. 실제 명단을 소스에 복사하지 마세요. 새 독립 설치는 `FILE_STORAGE=d1`과 `ADMIN_PASSWORD`만 설정한 뒤 새 학급 만들기를 사용합니다. 이전 데이터가 있는 저장소의 파일 저장 모드를 임의로 바꾸지 마세요.

## 별도 무료 시험 배포 (아직 계정 설정 필요)

1. Cloudflare 계정의 **Workers Free**를 확인합니다. Paid 변경, 카드 등록, R2 구독은 진행하지 않습니다.
2. 기존 운영 DB와 다른 **시험용 D1**을 만들고 `wrangler.external.jsonc`의 DB ID를 설정합니다. 설정의 임시 UUID로는 배포되지 않습니다.
3. D1에 `drizzle/`의 SQL을 순서대로 적용합니다. 새 파일은 추가 테이블·인덱스·제한 트리거만 만들며 기존 자료를 초기화하지 않습니다. 먼저 별도 시험 DB에서 검증하세요.
4. 환경 비밀값 `ADMIN_PASSWORD`를 설정합니다. 비밀번호는 GitHub Actions Secret/Cloudflare Secret에만 둡니다.
5. 다음 명령으로 독립 구성을 검사·빌드합니다.

```sh
pnpm check:free
pnpm build:external
# 실제 계정·무료 플랜·별도 DB를 확인한 뒤에만:
CONFIRM_WORKERS_FREE=yes pnpm deploy:external
```

독립 URL은 배포 도구가 반환하는 실제 `workers.dev` 주소를 사용합니다. 기존 Sites 주소는 유지합니다. 이 구성은 새 R2 리소스를 만들지 않습니다. 인증 해시와 프레임워크가 Free의 CPU 제한을 충족하는지는 실제 시험 URL에서 검증해야 하며, 실패하면 유료로 올리지 않고 원인을 먼저 분석합니다.

새 독립 설치에는 개인정보 없는 작성 길잡이 예시가 기본 제공됩니다. 기존 운영 사이트는 원래 승인된 공통 예시를 그대로 사용합니다. 실제 학급·예시를 독립 서비스로 옮기는 것은 별도의 비공개 백업·검증 작업이며 자동 이관하지 않습니다.

## GitHub와 안전한 배포

- 공개 저장소에는 정제한 현재 소스만 올리고 학생 정보가 포함될 수 있는 이전 개발 이력은 복사하지 않습니다.
- GitHub Actions는 테스트와 타입 검사·독립 빌드만 자동으로 실행합니다. 배포는 기본적으로 실행하지 않습니다.
- 수동 시험 배포 workflow는 무료 플랜 확인 입력, 별도 시험 D1 ID, Cloudflare 자격 증명이 모두 있어야 실행합니다. 기존 DB를 지우거나 운영 사이트를 교체하는 작업은 없습니다. 유료 러너와 유료 외부 액션을 사용하지 않습니다.
- 스키마 변경 전에는 D1 SQL과 파일 원본을 각각 비공개로 백업하고, 복원은 새 DB부터 확인하세요. 운영 DB에 파괴적 import를 자동 실행하지 마세요.
- Sites의 Git 원격과 GitHub는 별개입니다. GitHub에 올렸다고 Sites DB·파일이 GitHub로 이동하는 것은 아닙니다.

자세한 비용 근거와 실행 순서는 [운영 개선 계획](docs/운영_개선_계획.md)을 참고하세요. 공급자 무료 조건은 바뀔 수 있으므로 배포 직전에 공식 문서를 다시 확인합니다.
